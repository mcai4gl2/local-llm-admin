## M10 Task 3: eval statistics

### Problem/Goal
Scores from eval runs need an uncertainty interval, and two runs need a paired verdict (better, worse or no clear difference) that does not overreact to noise.

### Solution/Implementation
`eval_stats.py`: `mean_ci` gives a seeded percentile bootstrap (2.5% and 97.5%) of the mean. `paired` bootstraps per-case differences over shared cases only. Verdict is "better" when the interval is above zero, "worse" when below, otherwise "no clear difference". Single values and constant samples return a zero-width interval. Empty input raises `ValueError`. Outputs are rounded to 4 decimals.

### Results
Tests: 7 pass in `tests/test_eval_stats.py`, module at 100% line and branch coverage. Full suite 1882 passed, 1 skipped. Ruff and mypy (strict) clean.

### Files Modified
`src/local_llm_admin/eval_stats.py`, `tests/test_eval_stats.py`, `devlogs/2026-10-20.md`

### Fix: small-n verdicts and iters validation (Task 3 review round 1)

## Fix: M10 final review (regex safety, reasoning, scorecard keys, judge compare, promotion)

### Problem/Goal
The whole-branch review found five issues: `((a+))+$`, `(a|aa)+$` and `(a+){1,999}` passed the
text-based nested-quantifier check and froze the event loop while grading; reasoning reached a
grader when the template opened `<think>` in the prompt (only `</think>` in the reply) or a
thinking reply was cut off with no tags; the scorecard keyed cells by suite only, so thinking
on and off overwrote each other; compare ignored which judge graded each side; a model with
failed cases was still promoted.

### Solution/Implementation
- Regex check walks the parsed pattern (`re._parser`): no alternation inside a repeat; a
  repeat holding a repeat must be bounded at 100 or less and split one way (single characters
  and their repeats, each sharing no character with what can follow it). core-v1 still loads.
  Deterministic grading runs in `asyncio.to_thread`.
- `final_answer` keeps only the text after an unopened `</think>`; with thinking on, a
  `length` stop without `</think>` (and no separate reasoning) is "stopped while thinking".
  `thinking` added to `eval_results` and `eval_scores` (v14 amended in place, unreleased);
  runner, judge phase and regrade pass it.
- Scorecard cells `<suite>` / `<suite>+thinking` with suite version, thinking, judge,
  self-judged; Models tab shows thinking-off cells only; Quality tab marks all three.
- Compare: 409 "not comparable: judge differs" when the judge sets on graded judge rows differ;
  `self_judged: {a, b}` when either side is self-judged.
- A model with any `failed` row is not promoted (summary still written).
- Minors: choice letter case-sensitive (lower case only when alone, "I" not as the pronoun);
  README compare rule and Strata/MLX note; DESIGN no longer claims `reasoning_effort` is sent.

## Lessons Learned
- Text heuristics over regex source miss grouping tricks; check the parse tree.
- Bounded repeats are not safe on their own: `(a+){4}$` on 200 characters runs for tens of
  seconds, so the split-one-way rule matters as much as the bound.
- Anything that changes how an answer is graded (thinking) must be stored with the result, or
  regrade silently applies a different rule.
