## Strata engine (Qwen3.8-Flash-Next) — Phases 0–5

### Problem/Goal
Run Qwen3.8-Flash-Next on the Mac through Strata as a third exclusive engine next to MLX and
ComfyUI, measured first in an isolated sandbox (`plans/20261015_strata-qwen38-flash-next.md`).

### Solution/Implementation
- Phase 0: pinned Strata checkout and Q2_0 setup in a sandbox on the models volume with its own
  `HOME`/XDG/TMPDIR; MLX and the services stopped for the run and restored afterwards; endpoints
  captured with `ops/strata-phase0/capture.sh`, speed with `bench.py`, before/after snapshot diff.
- Phase 1: host wrapper `host/strata/bin/strata {start,stop,status}` (loopback `:8086`, env file
  parsed not sourced, refuses while another engine, a sidecar, the embedding service or an MLX
  lock is active; stop sends TERM then KILL and reaps the engine child); guards in `mlx-model`
  and `comfyui`.
- Phase 2: `EngineKind.strata`, `StrataClient`, switch plans that stop and restore sidecars and
  services, `STRATA_ENABLED` flag (off by default).
- Phase 3: status, badge, metrics, log source, alerts, availability, diagnostics, log rotation.
- Phase 4: test chat and the compatibility cases follow Strata (its base URL, key and model id).
- Phase 5: `LITELLM_LOCAL_MODELS` default gains `openai/qwen3.8-flash-next-q2_0`.

### Results
- Q2_0 on the M5 Pro 64 GB: ready 37 s after start; decode 57–66 tok/s; prompt 267 tok/s at 4K
  and 831 tok/s at 29K; memory pressure normal and swap flat; SIGTERM frees everything in 0.6 s.
  Full table in `docs/DESIGN.md` §3b. Per-user state unchanged by the experiment.
- Fixtures `tests/fixtures/strata/{health,metrics,models}.json` are now recordings.
- `capture.sh` bugs found in the run and fixed with tests: its IP scrub rewrote the version
  `0.1.44.1-metal`, and zsh passed the Accept header as one word (Prometheus capture got 401).
- Gates: see the final suite run in the ledger; nothing deployed.

## Lessons Learned
- An IPv4 scrub must not touch four-part version strings; anchor it against a trailing `-`/`.`.

- The Strata download dominated setup (2.5 h at 1.5–4.5 MB/s); the Metal build took minutes.
- Strata's own per-request statistics go to `app/strata-<pack>.log`, separate from the server's
  stdout that the wrapper logs.

## Strata IQ3_XXS trial at a 131072 context

### Problem/Goal
Run the plan's IQ3_XXS trial (Phase 0 steps 7–11) at 131072 with thinking on, and apply the
decision gate against Q2_0.

### Solution/Implementation
- Strata's setup with `--model IQ3_XXS --context 131072` in an internal-SSD sandbox, reusing
  the Q2_0 sandbox's checkout and Metal build. Setup leaves out the MTP draft layer when the
  experts stream (its own rule), so IQ3 decodes one token per step.
- Benched the standard cases, then `bench.py --needle 110000 --think`; three cold starts.

### Results
- Setup 2 h 6 min; 111 GB on the internal disk (GGUF plus the experts' streaming copy).
- Ready in 2–4 s (three cold starts, no errors); the first request waits ~12 s while the
  28 GB expert arena fills.
- Decode 26–32 tok/s; prompt 427 tok/s at 4K, 533 at 29K, 529–557 at 98.8K.
- 98.8K-token needle with thinking on found at every depth. Pressure normal, swap flat.
- Gate: fails on decode (< ~35 tok/s, 60% of Q2_0) and 4K prompt (< 500 tok/s). Q2_0 ships.

### Files Modified
- `docs/DESIGN.md` §3b, the plan's status line

## Lessons Learned
- On a 64 GB Mac, streaming costs IQ3_XXS about half of Q2_0's decode: no MTP drafts, and
  a quarter of the experts come from the SSD.

## Strata on the MLX URL (one LiteLLM route)

### Problem/Goal
The operator's LiteLLM has one route to the MLX server's `:8080`; switching engines should
change only what answers there, with no second route.

### Solution/Implementation
- `bin/strata` serves on `0.0.0.0:8080`. `STRATA_API_KEY` is optional (none: open on the
  LAN like MLX; an inherited key is never used); optional `STRATA_ALLOWED_HOSTS`.
- `bin/mlx-model` and `comfyui/bin/comfyui` recognise Strata's server by its command line,
  from its pid file or the `:8080` listener: `mlx-model stop` never kills it, start and
  select refuse with the Strata message, status does not report Strata's health as MLX's.
- Admin: `STRATA_API_BASE`/`STRATA_PORT` default to `:8080`; on the shared port the MLX
  check gives way to a live Strata pid file, Strata is found by its pid file only, and an
  MLX `/health` that says `service: strata` does not count.
- Deployed: host files, Strata env without a key, admin env without one, the admin.
- Plan decisions 4, 6 and 7 revised; DESIGN D7, host README and env examples updated.

### Results

## Engine control: pick the Strata pack

### Problem/Goal
Both packs are installed, but the Engine control showed one Strata entry; changing packs
meant editing `strata.env` by hand.

### Solution/Implementation
- Target `strata:<pack>` (`parse_target`, packs Q2_0 IQ2_XS IQ3_XXS IQ3_S). `plan_transition`
  takes the running pack: another (or unknown) pack restarts Strata with the chosen one,
  the same pack is "already active", and rollback starts the pack that ran.
- `StrataClient.packs()` lists the installed packs from the `app/strata-<pack>.json` run
  configs (read only) with their `--max-context`; status adds `pack` (from `/health`'s
  model id) and `packs`. Control reads the running pack before planning.
- `bin/strata start [pack]`: an unknown pack exits 2; the pack of a successful start goes to
  `run/strata.pack`, so a plain start (the watchdog's) runs it again. Status reads the
  context from the pack's run config. The intent stays `strata`.
- Dropdown: one entry per pack ("Strata · IQ3_XXS · 128K context", "(running)"); the Strata
  card shows the pack; the confirm text says LiteLLM keeps working through Strata.

### Results
- Tests first for every piece (plan, client, control, wrapper); `strataOptions` checked in a
  throwaway node container. Suite 1801 passed, 1 skipped, coverage 97.8%; ruff and mypy
  clean. Wrapper and admin deployed; Strata kept running through the deploy.
