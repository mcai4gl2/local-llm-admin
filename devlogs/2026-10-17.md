# 2026-10-17

## Plans: knowledge base (M9) and task-quality evals (M10)

### Problem/Goal
After a review of the admin's features, the operator picked two larger additions: a local
knowledge base (RAG) on top of the M8 embedding service, and evals that measure answer
quality per model, not only speed and API compatibility.

### Solution/Implementation
- `plans/20261017_knowledge-base.md`: separate `kb.sqlite` with FTS5 and float vectors;
  two-stage ingest (extract/chunk always, embed when the sidecar runs); hybrid search
  (BM25 + vectors, reciprocal-rank fusion, reranker) that degrades to keyword-only while
  Strata owns the GPU; answers with numbered citations; gateway API including
  `kb:<collection>` chat completions for LiteLLM. Extraction runs in a child process with
  a timeout. Phase 0 checks FTS5 and macOS folder privacy on the Mac.
- `plans/20261017_task-quality-evals.md`: `kind="eval"` quality runs reusing the runner's
  slot, switching and restoration; versioned suites with deterministic graders (exact,
  regex, choice, number, JSON fields, tool call) and an optional judge (external or a
  local MLX model in a second phase); stored responses for re-grading; bootstrap intervals,
  paired comparison, scorecard; built-in `core-v1` (25 cases), `writing-v1` (judge) and
  `needle-v1` (generated long-context cases).

### Results
- Checked in the dev container while writing: the KB chunker in the plan passes the plan's
  own chunking tests. The eval graders (run outside the repo with stub spec classes) pass
  the plan's grader tests.
- Two bugs found in the drafts and fixed: a regex with a literal triple backtick that
  would have closed its Markdown code block, and a nested-quantifier rule that refused
  `core-v1`'s own bounded `(...){4}` pattern.
- The private leak-pattern file is not on this workstation, so `check_public.py` was not
  run; a manual scan for addresses, home paths, emails and keys found nothing.
