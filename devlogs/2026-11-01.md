## Drain Before Switch and Configurable Inference Admission

### Problem/Goal
The shared inference gateway counted active requests privately, so engine jobs could stop
an engine while admitted gateway work was still resolving or streaming.

### Solution/Implementation
Added an atomic admission registry, per-backend concurrency settings, a bounded drain
barrier, pending-drain cancellation, persistent unavailable state, and Models progress.
Manual lifecycle, engine selection, quality-run entry, and watchdog starts use the
barrier. Documented gateway-only coverage and rollback behavior.

### Results
The full devcontainer gate passed: 3,863 tests passed, 4 skipped, 97.19% coverage;
admission and inference gateway had 100% statement and branch coverage. Ruff, strict
mypy, and the private-pattern public scan passed. The approved admin deployment
completed, and installed gateway files matched the worktree. Live smoke, cancellation,
and a temporary five-second timeout passed with the original private environment
restored. A live switch was refused before drain by the existing memory-pressure guard;
completed stream-before-switch and failed target readiness remain unqualified.

### Files Modified
src/local_llm_admin/admission.py, inference_gateway.py, control.py, quality_runner.py,
app.py, config.py, Models UI; tests/test_admission.py, test_inference_gateway.py,
test_control.py, test_app.py; docs/shared-inference.md, a rollout report, ops/env.example,
and the active plan and indexes.

## Lessons Learned
The gate must begin closed before concurrent listeners start and persist its unavailable
marker before a job is submitted. Gateway transport cleanup alone does not establish
native all-client quiescence. Live resource guards may limit qualification even when
the new barrier behaves correctly.
